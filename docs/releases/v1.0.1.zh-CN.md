# Quanterdeck v1.0.1 — 2026-10-11

[English](v1.0.1.md) · [简体中文](v1.0.1.zh-CN.md)

## 框架固定版本升级至 OpenQuanter 2.0.1

- 框架依赖固定到 OpenQuanter `v2.0.1` 的 release commit
  `b60fdf48719a9ca116cd24b7ccb2b600f1273e53`。包含精确净额记账、原生手续费／资金费
  恢复与覆盖证据、可比较的仓位读取边界、L2 缺口／快照处理，以及 warm-up
  决策和研究证据关联诊断。（[#74](https://github.com/openquanter/quanterdeck/pull/74)）
- Journal 与成交页面识别规范成交、账本初态、手续费证据、资金费证据／恢复及待决
  资金费义务。缺失成交手续费和不可用的历史资金费模型继续明确显示为不可得，不显示
  为零。恢复交易提示说明交易进程要求新鲜且成交 revision 匹配的仓位核对。
  （[#74](https://github.com/openquanter/quanterdeck/pull/74)）
- 保留之前引入的框架改进：破产价强平结算、累计尝试折减、做市胜出者 markout
  闸门，以及按结论比较保真档位。（[#73](https://github.com/openquanter/quanterdeck/pull/73)）
- 框架发布和控制台发布继续在上游版本卡中独立显示。版本升级不意味着历史生产
  G12 验收通过。（[#74](https://github.com/openquanter/quanterdeck/pull/74)）
- **参数扫描页读取 sweep v2 文件**：展示折减统计计入的尝试次数（本次 sweep 和
  累计 ledger），以及胜出者的 markout 和用于判定它的阈值。仍能读取 v1 文件，
  并说明这些信息当时未记录。（[#73](https://github.com/openquanter/quanterdeck/pull/73)）

## 同一主机上的多个交易进程

- **代理通过控制 socket 发现所有交易进程。** 新的 `traders` 读取按 socket 名称
  返回各进程状态；无应答的进程也列出原因。`status`、`orders`、`metrics`、
  `attribution`、`halt`、`resume`、`shutdown` 接受可选 `trader`：不提供时保留原行为，
  但存在多个进程时会拒绝并列出名称；不指定时请求中不包含该字段，旧代理仍能读取。
  （[#72](https://github.com/openquanter/quanterdeck/pull/72)）
- **Watch 分别监测每个交易进程。** Black box 的交易进程记录与事件携带 `id`，
  各进程只与自己的上一个样本比较；moment 同时展示各进程最后一个样本，告警 key
  和消息指明进程，如 `halted:<id>`。仅一个进程时保持兼容：不增加 `id`，key 不变。
  （[#72](https://github.com/openquanter/quanterdeck/pull/72)）
- **交易进程页**按策略和 symbol 分组，展示状态、持仓、权益、净盈亏、仓位检查和行情。
  （[#72](https://github.com/openquanter/quanterdeck/pull/72)）

## 每个周期写入报告，而不只是展示

- **持久化产物。** 每隔 `OQ_DECK_REPORT_HOURS`（默认 24，按 UTC 对齐；`0` 关闭，
  最大 168），控制台将刚结束周期的报告写入 `OQ_DECK_REPORTS_DIR`（默认状态目录下
  的 `reports`）。启动约一分钟后，如该周期尚无报告，也会补写一次。通过临时文件
  加重命名保证完整写入，文件仅属主可读写，保留 90 天。
  （[#71](https://github.com/openquanter/quanterdeck/pull/71)）
- **报告内容。** 周期内净盈亏、已实现盈亏、手续费、资金费（跨重启按 run 累计），
  首末权益与权益曲线，期末交易进程状态，生成时 reconciliation 判定（与
  `/live/latest` 相同的比较），告警、halt、自检分歧及服务启动／停止，以及主机最高
  负载、最少可用内存和最少空闲磁盘。输入来自主机代理 black box（actor
  `deck:report`）与 journal；无法读取的部分在 `unavailable` 中记录原因，数值缺失
  而非填零。（[#71](https://github.com/openquanter/quanterdeck/pull/71)）
- **读取时渲染。** 存储为 JSON，请求时生成独立 HTML 页面：内联 CSS、内联 SVG
  图表、明暗主题，无脚本和外部请求。按 `Accept-Language` 或 `?lang=zh|en` 选择
  语言，并使用独立的 `Content-Security-Policy: default-src 'none'; style-src
  'unsafe-inline'; img-src data:; sandbox`。
  （[#71](https://github.com/openquanter/quanterdeck/pull/71)）
- **路由。** `GET /api/v1/reports`、`GET /api/v1/reports/{id}`（页面）、
  `GET /api/v1/reports/{id}/data`（JSON）；id 必须与目录列表匹配，不直接拼接文件路径。
  `POST /api/v1/reports/generate` 为当前结束的周期生成报告：如其他写入一样检查
  `Host`、`Origin` 和 session，但不受 write mode 限制（不改变主机状态）；每分钟
  最多一次，超出返回带 `Retry-After` 的 429。新增 `reports` capability、诊断下的
  报告页及设置项。（[#71](https://github.com/openquanter/quanterdeck/pull/71)）

## Black box 将各样本与上一个样本比较

- **检查每个交易进程的连续样本。** 无成交却发生持仓或已实现盈亏变化、累计计数器
  回退、净盈亏不等于已实现 − 手续费 + 资金费，都属于分歧：记录在样本中，并在
  复盘时间线生成 `selfcheck_disagree` 事件和 `selfcheck` 告警。样本间发生重启、
  手续费未知或字段缺失时是“无法判定”，不算一致。复盘页面的 moment 面板会展示。
  （[#69](https://github.com/openquanter/quanterdeck/pull/69)）

## 告警也发送到 Telegram

- **Discord 之外的第二渠道。** 同时设置 `OQ_AGENT_TELEGRAM_CHAT` 和
  `TELEGRAM_BOT_TOKEN` credential 时，代理将所有消息（告警、恢复、审计动作、渠道
  测试）也发送到该 chat。使用纯文本，带 `oq-agent · <host>` 页脚，截断至 Telegram
  的 4096 字符限制。仅配置其中一个时，启动警告指明缺少哪一项，Telegram 保持关闭。
  （[#70](https://github.com/openquanter/quanterdeck/pull/70)）
- **一个渠道失败不阻塞另一个。** 每条消息尝试发送到所有已配置渠道，逐渠道记录
  失败。Token 是 Telegram 请求 URL 的一部分，因此输出错误前会去除它，sink 的
  `Debug` 也会隐藏 Token。（[#70](https://github.com/openquanter/quanterdeck/pull/70)）
- **离机锚仍在 Discord。** 审计与 journal 的离机锚仅从 Discord 读回；Telegram
  bot 无法读取 chat 历史，所以能承载告警，不能作为锚。
  （[#70](https://github.com/openquanter/quanterdeck/pull/70)）
- **告警页说明已配置渠道。** 代理的 alerts 视图新增 `channels`（`["discord",
  "telegram"]`；仅打印告警时为空）。旧代理显示为“未报告”，而不是“没有渠道”。
  （[#70](https://github.com/openquanter/quanterdeck/pull/70)）
