# 界面重构 v4：信息架构、交互与视觉

> 状态：2026-09-25 定稿，按本文实现。取代 v3 之后逐步堆出来的平铺导航。
> 判定规则（"无法判断"不渲染成"一致"、残差未知不是 0 等）仍以 [UI-BRIEF](UI-BRIEF.zh-CN.md) 为准，本文不改规则，只改组织方式和外观。

## 1. 问题

v3 之后功能一项项加进来，每加一项就在侧栏多一行，结果是：

- **导航是 19 个平铺条目**，没有分组，顺序既不是使用频率，也不是任务流程。"运维 / 挂单 / 日志 / 部署 / 审计"和"运行记录 / 参数扫描"混在一起。
- **同一件事分散在多页**：交易进程的状态在"运维"，挂单在"挂单"，成交在"实盘对账"，盈亏在"运维"，行情质量在"数据质量"。看一眼实盘在干什么要翻四页。
- **总览答非所问**：打开首页看到的是"运行记录 6""合计已实现盈亏 —（无法合计）""写入模式 已开启"——这些是研究数据和配置，不是操作者每天第一件想知道的"交易正常吗"。
- **两个"一致"并排却不说明区别**："实盘对账 一致"和"持仓核对（进程内）一致"是两件不同的事（journal 对交易所；进程内存对交易所），界面上看不出。
- **新手/专家开关**把术语解释以大段文字塞进卡片标题，卡片被撑乱；而专家模式又什么提示都没有。
- **视觉原始**：没有图标、没有页面级操作区、卡片只有边框、表格没有层次、状态只靠文字颜色。

## 2. 定位与使用习惯

**这是一个人的交易主机控制台**，不是多租户 SaaS。一个操作者，一台交易主机（当前是测试网），加上研究产物（回测 run、参数扫描）。

按频率排列的使用场景：

| 频率 | 场景 | 要在几秒内回答的问题 |
|---|---|---|
| 每天多次 | 看一眼 | 交易进程在跑吗？有告警吗？对账一致吗？赚了还是亏了？ |
| 每天 | 看实盘 | 持仓、挂单、最近成交、盈亏、行情是否新鲜、风控限额 |
| 出事时 | 处置 | 停机 / 解除 / 重启服务——就在看到问题的地方点 |
| 出事后 | 查原因 | 哪条告警、什么时候、那一刻系统和进程在做什么、日志说了什么 |
| 每周 | 变更 | 改配置、发布新版本、把策略推进一步 |
| 不定期 | 研究 | 回测对比、参数扫描是否过拟合 |

设计原则由此而来：

1. **首页只回答"正常吗"**，并且每个"不正常"都能一键跳到处理它的地方。
2. **一个对象一页**：实盘是一页，不再拆成运维/挂单/对账/数据质量。
3. **操作放在对象旁边**：停机在交易进程状态旁，重启在服务那一行，回滚在版本那一行。
4. **全局状态常驻**：顶栏始终显示环境（测试网/主网）、主机、交易进程状态、告警数，在任何页面都不需要回首页确认。
5. **解释按需出现**：术语旁边一个 ⓘ，悬停看一句人话；去掉新手/专家开关。

## 3. 信息架构

侧栏分组、带图标，组名是任务而不是技术名词：

```
总览                         仪表盘：正常吗
交易
  实盘                       状态、盈亏、持仓、挂单、成交、行情、风控限额（标签页）
  对账与归因                  交易所对账 | 盈亏归因（标签页）
诊断
  告警                       当前、历史、规则、渠道
  黑匣子复盘                  任一时刻的系统与进程
  日志                       服务输出与日志文件
  事件回放                    journal 逐条
变更
  策略与上线                  门控流水线
  配置                       策略配置、备份、回滚
  发布                       版本、部署、回滚
研究
  回测记录                    run 列表、详情、对比、markout
  参数扫描                    .sweep 结论与参数表
系统
  主机与服务                  服务启停、主机资源、资源曲线
  交易所账户                  密钥指纹
  审计日志
  设置
```

v3 → v4 的对应：运维 → 实盘（交易进程部分）+ 主机与服务（服务与主机部分）；挂单 → 实盘·挂单；实盘对账 → 对账与归因·交易所对账（成交流水移到实盘·成交，行情移到实盘·行情）；归因 → 对账与归因·盈亏归因；数据质量 → 实盘·行情；部署 → 发布；Journal 回放 → 事件回放；账户 → 交易所账户。

能力表仍然驱动导航：做不到的条目不出现，整组都做不到时整组不出现。

## 4. 页面

### 4.1 顶栏（全局）

左：当前页标题。右：`测试网 · <主机名>` 环境标签（主网用红色）、交易进程状态胶囊（交易中 / 已停机 / 无应答，点击到实盘）、告警铃铛带数字（点击到告警）、只读标记（写入未开启时）、用户菜单（设置、登出）。

### 4.2 总览

1. **状态横幅**：交易进程状态 + 策略、合约、环境、已运行多久、最近行情多少秒前；右侧"停机"按钮（写入开启时）。已停机时横幅变红并写明原因和"解除停机"。
2. **关键指标**一行：本次运行盈亏、权益、持仓（多/空分开）、挂单数，每个带 ⓘ。
3. **健康检查清单**：每项一行，圆点 + 名称 + 结论 + 时间 + 跳转箭头。
   - 行情：最近一笔多少秒前、读不出的消息数
   - 交易所对账：journal 重建的持仓 vs 交易所最新读数
   - 进程自检：进程内存里的持仓 vs 它自己定时向交易所查询的结果
   - 交易日志：可写
   - 服务：N/N 在运行
   - 主机：负载、内存、磁盘、时钟
4. **告警**（当前 + 最近 5 条历史）与 **最近动态**（成交、操作审计、服务启停事件，按时间倒序）并排。
5. **资源**：交易进程与主机过去 24 小时的内存/CPU 小图（来自黑匣子）。

研究相关的数字（run 数、合计盈亏）移到"回测记录"页头。

### 4.3 实盘

页头：状态 + 操作（停机 / 退出 / 解除停机）。指标行同总览。标签页：

- **持仓与挂单**：持仓表（腿、数量、均价——来自 journal 重建）；挂单表（方向中性色、价格、数量、腿、平仓标记、挂出时间）。
- **成交**：成交流水（分页）。
- **行情**：最近价格走势小图、延迟分布、间隔、乱序/重同步/读不出计数。
- **风控**：生效中的限额、发单计数、外来订单、策略在等待什么。

### 4.4 对账与归因

标签页"交易所对账"：顶部结论（一致 / 不一致 / 无法判断）+ 两栏对比（进程认为 vs 交易所）；选择 journal；粘贴对账折叠在"手动对账"里。标签页"盈亏归因"：来源切换（实时 shadow / 两份 run 文件）+ 瀑布图 + 五个成因三态。

### 4.5 其余页面

保持现有功能，统一为：页头（标题、一句用途、主操作）→ 卡片 → 表格；空态/错误态统一；时间统一为"相对时间 + 悬停看绝对时间"。

- 告警：当前告警卡片（静默按钮在行内）、历史表、规则表、渠道测试按钮在页头。
- 黑匣子复盘：时间范围选择器在页头；曲线改用 echarts（悬停提示、可缩放）；点选时刻在右侧抽屉展开快照、决策与成交、程序输出。
- 日志：来源下拉（服务输出 / 日志文件）+ 过滤 + 跟随，全高终端样式。
- 发布：当前运行版本卡片（版本、构建、签名、部署时间、回滚按钮），待部署列表（部署按钮在行内），最近一次部署的步骤时间线。
- 主机与服务：服务表（状态点、运行时长、内存、CPU、操作按钮），主机资源卡，资源曲线。

## 5. 视觉系统

- **两套主题，默认浅色**：浅色参照 Google 的风格——浅灰蓝底、白色卡片、Google 蓝作强调；深色保留给长时间盯盘。顶栏可切换浅色 / 深色 / 跟随系统，选择记在本机浏览器。两套主题共用同一组颜色变量，图表从当前主题读色。终端样式的输出面板在两套主题下都保持深色。
- **彩色小图标**：卡片标题、指标、健康检查磁贴、动态时间线都配一个带浅色底的图标，颜色取自一组与状态无关的色相（蓝、紫、青、橙、粉……），只用来区分，不表示好坏；侧栏按分组着色。
- **数据图表与实时展示**：总览有实时价格与挂单价位图（5 秒刷新）、本次运行盈亏走势、指标卡的 24 小时趋势小图、健康评分环、内存与磁盘用量环；实盘页同样有价格与挂单图和盈亏走势。
- **字号**：正文 14px，表格 13px，页标题 20px，指标数值 24px；数字用等宽数字（tabular-nums），不整段用等宽字体。
- **圆角** 8px；卡片有标题栏（标题 + 右侧操作），内边距 16–20px。
- **颜色语义**只用于状态：绿=正常、琥珀=注意/无法判断、红=故障/亏损、蓝=可操作/选中。买卖方向保持中性（UI-BRIEF §8）。
- **图标**：lucide-react（MIT，按需打包）。侧栏每项一个图标，状态用圆点 + 文字，不只靠颜色。
- **组件**：`PageHeader`、`Card`、`Stat`、`StatusDot`、`Badge`、`Tabs`、`DataTable`、`Button`（主要 / 次要 / 危险 / 幽灵）、`Tooltip`、`Drawer`、`EmptyState`、`ErrorState`、`Skeleton`。页面只拼组件，不再各自写 Tile。
- **刷新**：每页页头右侧显示"自动刷新 · N 秒前"，数据陈旧时变琥珀。

## 6. 实现顺序

1. 设计系统组件 + 外壳（分组侧栏、顶栏）+ 总览。
2. 实盘、对账与归因。
3. 诊断组（告警、黑匣子复盘、日志、事件回放）。
4. 变更组、研究组、系统组。

每一步：构建 → 在真实数据上截图核对 → 合并 → 部署。旧路由重定向到新位置，书签不失效。
